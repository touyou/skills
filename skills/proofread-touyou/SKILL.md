# touyouさんの文章をAI臭を残さずに校正する

touyouさんが「いきおい」で書いた日本語の文章は、本人の口語的なリズム・ゆらぎ・留保が文体の核になっている。AIに校正させると「読みやすさ」のために**講義モード**（教師モード）の表現が混入し、本人の肉声が失われる。このスキルはそれを防ぐ。

## 鉄則：迷ったら触らない

「読みやすくしたほうがいいかな」と迷ったら**触らない**のが正解。touyouさんの文章は「読みやすさ」より「自分らしさ」が優先される。整えすぎが一番のNG。

## やってはいけない4つの操作（強いAI臭）

校正中、以下の操作は**絶対にしない**。これらが「AI臭」の正体。

### 操作1：メタな進行管理を追加しない

文章自身が「いまから何をするか」を読者に逐一案内する書き方は、講義スライドのリズム。touyouさんの散文には混ぜない。

❌ 追加してはいけない表現:
- 「ここで〜紹介します」「ここで〜したい」「ここからが大事なんですが」
- 「これが本質」「ここが大事」「ポイントは〜」
- 「視点を切り替えたい話があります」
- 「〜について詳しく見ていきましょう」

❌ 見出しを「これが本質」型のキャッチコピーに書き換えない:
- ✕ 「機械学習の正体──これが本質」
- ◯ 「機械学習の正体」（本人がつけた見出しはそのまま尊重）

❌ 「ためて明かす」型（もったいぶった気づきの開示）を追加しない:
- ✕ 「ここまで作ってみて、気づいたことがあります。変わったのはデザインシステムの読み手だということです。」
- 情報ゼロの予告文（「気づいたことがあります」「一つ発見がありました」）で一拍ためてから、分裂文（「変わったのは／大事なのは／面白いのは 〜 だということです」）で種明かしする構成。プレゼンのドラムロールのリズムで、散文に混ざると強いAI臭になる
- ◯ touyouさんなら予告せずそのまま書く: 「ここまで作ってみて、デザインシステムの読み手が変わったなと思いました」
- 元の文章に残っている場合の検出は「指摘していいもの」の 8 を参照

### 操作2：念押しの言い換え反復を追加しない

書き手が1度言ったことを、太字や言い換えで2度3度と念押しするのはAIの癖。touyouさんは1度言ったら次に進む文体。

❌ 新規追加してはいけない接続:
- 「つまり〜」「言い換えると〜」「すなわち〜」
- 「〜というわけです」「〜ということです」
- 「ようするに〜」（既にあるなら残してOK、新規挿入が禁止）

元の文章にこれらの語が既にある場合は残す。「校正」を理由に削るのもNG。**新規挿入だけ禁止**。

### 操作3：流れの切断＋ラベル化をしない（最重要・最も気づきにくい）

これが一番気づきにくいAI臭の混入経路。要注意。

❌ **連用形を句点で切らない**:
- 元: 「〜決められるだけで、理論上は何でもできる」
- ✕ 校正後: 「〜外的要因のみ。理論上は何でもできる」

連用形（〜だけで、〜るので、〜ながら）でつないだ長文は、touyouさんの「列挙したまま流れていく」リズムの本体。これを句点で切ると講義モードに変わる。

❌ **列挙を抽象名詞でまとめない**:
- 元: 「時間・フレームワークやOS・処理能力で決められる」
- ✕ 校正後: 「時間、フレームワーク、OS、処理能力**といった外的要因**で決められる」

「外的要因」のような抽象ラベルを勝手に挿入しない。touyouさんの文体は列挙を列挙のまま流す。

❌ **体言止めで受けない**:
- ✕ 「〜というのが現状。」
- ◯ 「〜というのが現状です。」

体言止めへの変換は、文の重心を「整理されたラベル」に寄せる操作。touyouさんは体言止めをほぼ使わない。

❌ **一文を分割しない**:
- 元の文章で読点や接続詞でつながっている長文を、複数の短文に分けない
- 留保（「〜ですが」「〜とはいえ」「〜けれど」）が一文に複数あっても、それは意図的なゆらぎ

### 操作4：書いてないことを追加しない（明示許可制）

❌ 段落末に「重要なのは〜」「ポイントは〜」「結局は〜」などの決め台詞を勝手に追加しない。
❌ まとめ段落／結論段落を勝手に新設しない。
❌ 太字の強調を勝手に増やさない。

ただし、touyouさんから明示的に「ここに決め台詞欲しい」「強調を入れて」と頼まれた場合のみOK。**デフォルトは追加しない**。

## 保護する表現リスト（touyouさんの文体特徴）

校正中、以下は**絶対に書き換えない**。これらは touyouさんの肉声。

### 一人称
- 「**自分は**」「**自分が**」「**自分の**」「**自分も**」
- → 「私は」「筆者は」「僕は」に変えない、主語省略もしない（明らかな冗長以外）

### 文末
- 「〜と思います」「〜と思いました」「〜と思っています」
- 「〜してもらえればと思います」「〜してみてください」
- 「〜なのではないでしょうか」「〜じゃないかなと思います」
- → 「〜です」「〜でしょう」「〜と考えられます」「〜と言えるでしょう」に硬化させない

### 口語的副詞・砕けた表現
- 「**本当に**」「**ちょっと**」「**結構**」「**めっちゃ**」「**わりと**」「**けっこう**」
- 「**ぶっちゃけ**」「**ようするに**」「**ちょっとばかし**」「**そもそも**」
- → 削除や硬化をしない（「実に」「相当」「概ね」などへの置換禁止）

### 柔らかい指示語
- 「ところ」「やつ」「もの」「こと」「あたり」「感じ」
- → 「領域」「対象」「事項」「観点」に変えない

### 動詞
- 「考える」「使う」「やる」「作る」「書く」「触る」「見る」
- → 「検討」「活用」「実施」「制作」「執筆」「使用」「確認」に漢語化しない

### カッコ書き
- touyouさんはカッコ書きで補足説明を入れる癖がある（「（HCI）」「（Chief Design Officer）」など）
- → 親切心からの補足なので削らない、整理し直さない

### 接続詞
- 「**ただ**」「**ですが**」「**では**」「**というわけで**」「**そこで**」「**もちろん**」
- → 「したがって」「ゆえに」「そのため」「結果として」に硬化させない

## 指摘していいもの

以下は積極的に指摘してOK:

1. **誤字脱字、変換ミス**
2. **文法的に明らかに変な箇所**（主語と述語が合わない、助詞の使い方がおかしい等）
3. **事実誤認・固有名詞の誤りの疑い**（断定はしない、「〜では？」と疑問形で）
4. **同じ語の連続使用で読みにくい箇所**（書き換え案ではなく「同じ表現が3回続いてます」と指摘するだけ）
5. **意味が明らかに通らない文**（書き手の意図を確認するための質問として）
6. **表記ゆれ（同じ語の不統一）**（例:「ウィジェット」と「Widget」、「技術債」と「技術的負債」が同じ記事内で混在）。「どちらかに揃えては？」と指摘するだけで、勝手にどちらかへ寄せない。揃える方向は本人に委ねる
7. **読者が辿れない／別物に見える参照**（例: WWDC セッション番号を `(#343)` と書くと GitHub の issue 参照に見える、`実機 (R)` のような凡例なしの略号）。「これは読者に何を指すか伝わる形か？」と確認するだけ
8. **AI臭の残留パターン**（AIと共作したドラフトに混ざりがちな型）。代表例は「ためて明かす」型: 「気づいたことがあります。変わったのは〜だということです。」のような、情報ゼロの予告文＋分裂文の種明かし（「やってはいけない4つの操作」の操作1に定義あり）。見つけたら「ここはAI臭が残ってるかも」と指摘し、予告なしの一文に畳む案（「〜が変わったなと思いました」）を並記する。ただし touyouさん本人の肉声（「〜と思います」等の留保）と混同しない。疑わしい程度なら指摘せず流す

> 6・7 は日本語技術文書の校正観点（k16shikano 氏の [SKILL](https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d) より）を **「指摘のみ」** で取り入れたもの。正書法そのもの（漢字／ひらがなの使い分け、一文の長さ、体言止め、接続詞の選択）は touyouさんの文体として**保護対象**なので、技術文書ルールを口実に直さない。取り入れるのは「同じ記事内での不統一」と「読者が辿れない参照」だけに限る。
>
> 表記・用語・参照の一貫性で深く迷ったら [`references/japanese-tech-writing.md`](references/japanese-tech-writing.md) を見る。**A 節（取り入れる・指摘のみ）だけ使い、B 節（文体として保護）は適用しない**。

書き換え案を出すときの作法:
- 必ず元の表現を残し、「こうしてはどうか」と並記する
- 文体・リズム・ゆらぎは触らないことを明示
- なぜそう直したいかの理由を添える
- **保護リストの表現には触らない**

## 出力フォーマット

該当する指摘がある節だけ出す。指摘がなければその旨を短く返す。行番号を取得できない場合は段落と原文の引用で場所を示し、行番号を創作しない。事実を確認した場合は出典を添え、未確認の疑いと区別する。

```
## 校正結果

### 誤字脱字
- L〜「○○」→「××」（変換ミスかと）

### 文法的に変かもしれない箇所
- L〜「〜〜」: 主語が不明瞭です。「自分は」を補ってはどうでしょうか

### 事実確認したい箇所
- L〜「〜〜」: ××年は△△年では？

### 表記ゆれ・読者が辿れない参照
- L〜「○○」と L〜「××」: 同じ概念が違う表記。揃えるなら本人の好みで
- L〜「(#343)」: WWDC セッション番号が GitHub issue 参照に見えるかも（読者にどう伝わるか）

### AI臭が残ってるかもしれない箇所
- L〜「気づいたことがあります。変わったのは〜だということです。」: ためて明かす型。「〜が変わったなと思いました」のように予告なしの一文に畳んでは

### 触らない方針の箇所（参考）
- 「ぶっちゃけ」「自分は」「〜と思います」「ちょっと」などは保護対象として触っていません
```

## 新規執筆との境界

新規執筆・構成を変えるリライトは [write-touyou](../write-touyou/SKILL.md) が担当する。校正依頼だけで全面改稿しない。修正を反映する依頼なら明確な誤字・文法だけ反映し、事実・意味・表記の判断が必要な箇所は提案として残す。ユーザーが指定した文体変更は保護ルールより優先する。
