# AI臭の語彙・構文パターンと意味保持（touyou 用・柵つきリファレンス）

`writing-pack`（**proofread-touyou** / **write-touyou**）共有のリファレンス。nanaism 氏の [yomiyasu](https://github.com/nanaism/yomiyasu)（MIT）から、**touyou さんの文体と矛盾しない部分だけ**を取り入れて再構成したもの。

## 目次

- 使い方（最重要）
- A 節：取り入れる（A1. 意味保持の 4 点 / A2. 比喩動詞と直訳語 / A3. 非生物主語 / A4. 質感・認知を装う語 / A5. 英語直訳の構文 / A6. 後置ラベリング / A7. 間を作るだけの読点 / A8. 2026 年に増えた言い回し / A9. 漢語と和語は原文のまま）
- B 節：取り入れない（touyou さんの文体と衝突する）
- 出典

## 使い方（最重要）

- yomiyasu は「AIが書いた文を、誰が読んでも引っかからない平易な文へ書き直す」スキル。touyou の writing-pack は「touyou さんの肉声を守る／肉声で書く」スキル。目的が違うので、**丸ごとは適用しない**。
- 開くのは次の 2 場面だけ:
  1. 書き換え案を出す・リライトする前後に、**意味が変わっていないか**、案で語を硬くしたり開いたりしていないかを点検するとき（A1・A9）
  2. AIと共作したドラフトに**AI寄りの語彙・構文が残っていないか**を見るとき（A2〜A8）
- スキルによって使い方が反転するのは `japanese-tech-writing.md` と同じ:

| | A 節（採る） | B 節（採らない） |
|---|---|---|
| **校正（proofread-touyou）** | 見つけたら**指摘する**。書き換え案は A1 を守って並記するだけ | **適用しない**（touyou さんの文体は保護リスト優先） |
| **生成（write-touyou）** | 最初から**書かない**。リライト時は A1 を守る | **適用しない**（肉声の積極使用が優先） |

- 優先順位: **保護リスト・個人辞書 ＞ このリファレンス**。語があるだけで指摘する前に、AI 以前の本人の使い方（[`voice-baseline.md`](voice-baseline.md) 2 章）と比べる。A 節のリストに載っている語でも、touyou さんが個人辞書で「自分がよく使う表現」に入れていれば触らない。

## A 節：取り入れる

### A1. 意味保持の 4 点（書き換え前後のチェック）

書き換え案を出す・リライトするときは、元の文の次の 4 点を確かめ、書き換え後も同じに保つ。他のルールはこの 4 点を変えない範囲でだけ使う。

1. **主張**（何を言っているか）: 論点を別の概念にすり替えない（「本質」を「目的」にする等）。
2. **比重**（何を一番大事にしているか）: 否定していたものを「Aに加えてB」と並べたり、「AよりB」と順位をつけ直したりしない。
3. **言い切りの強さ**（断定・推量・可能性）: 言い切っている文を「〜おそれがあります」に弱めない。「〜と思います」「〜かな」を断定に上げない。touyou さんの留保はこの軸で守られる。
4. **文の働き**（評価・説明・依頼・予定・感想）: 「〜が大事」という評価の文を「〜を目指す」という予定の文にしない。

加えて、**語の含み**を残す。「うっかり」の不注意、「ようやく」の待ちくたびれた感じ、「〜てしまった」の後悔、「地味に」の目立たないけど確かにある感じ。比喩の語を言い換えるときも、その語が運んでいた含みは別の言葉で残す。

元の文から分からない動作主・名詞・原因・条件・数値・例は**足さない**。足したくなったら本文で補わず「書き手に確かめたい点」として外に出す（多くても 2 点まで。迷った点がなければ出さない）。

### A2. AI偏愛の比喩動詞と直訳語

抽象的な事柄や技術操作を比喩動詞で言う癖。AIと共作したドラフトに残りやすい。

| AI寄りの言い方 | 例 | 開く方向（含みは残す） |
|---|---|---|
| 倒す | 「安全側に倒す」「残さない側に倒す」 | 「〜を優先する」「〜に寄せる」 |
| 効く／効いてくる | 「地味に効きます」 | 「地味に役に立つ」「じわじわ助かる」 |
| 溶かす | 「丸一日溶かした」 | 「丸一日かかってしまった」（後悔の含みを残す） |
| 潰す | 「1つずつ潰していく」 | 「1つずつ直していく」 |
| 静かに壊れる | 「データが静かに壊れる」 | 「気づかないうちに不整合が起きる」（言い切りの強さは保つ） |
| 黙って〜される | 「黙って無視される」 | 「知らないうちに無視される」。エラーや通知が出ないと元の文から明らかなときだけ「エラーを出さずに」。「静かに」「黙って」をこう開くのは、システムやデータの不具合で知らせが出ないことをぼかしているときだけ。人や物の様子の「静かに」はこう開かない（原文にない「気づかなかった」の含みが入るため） |
| 前提が崩れる | 「この前提が崩れています」「基盤が崩れやすい」 | 前提にしていた条件や数値が前後の文にあるときだけ、それを主語にして「〜は当てはまらなくなりました」と書く。中身がなければ言い換えずに「何が成り立たなくなったのか」を尋ねる。「崩壊」「破綻」のような原文より強い語にしない |
| 沈黙する | 「静かに沈黙する」 | 「何も出さずに止まる」（原因を勝手に狭めない） |
| 〜した瞬間 | 「保存した瞬間に」（*the moment*） | 「保存するとすぐに」「保存した時点で」 |
| 正本 | 「〜を正本にする」（*single source of truth*） | 「〜を唯一の情報源にする」 |
| 耐力のある／構造を支える | （*load-bearing*） | 「外せない」「根っこにある」 |
| 穴を埋める | 「この穴は埋まりません」 | 「〜という挙動は変わりません」（何が起きるかをそのまま書く） |
| 付いてくる | 「スワイプで閉じる操作も付いてきました」 | 「〜も可能になりました」。当たり前の副産物をおまけのように語らない |
| 〜へ送る | 「設定を先に送ります」 | 「優先度を下げました」。実際に使った手段（API・設定）の言葉で書く |
| 場所のたとえの名詞 | 「設定の入口」「通知の受け口」 | 実物の名前（「設定画面」「通知を受け取る関数」）。「駅の入口」「依存先」のような定着した言い方は残す |
| 英語の術語に当てた漢字 1 字 | 「今回の版では」（*version*）、「一覧の頭」（*head*）、「lint の印」（*mark*）、「修正の枝」（*branch*）、「PR の題」（*title*）、「見出しの下の罫」（*border*） | 「バージョン」「先頭」「指摘」「ブランチ」「タイトル」「罫線」。「第2版」「目印」「木の枝」「作文の題」のような字どおりの使い方は残す |
| 英語の術語に当てた 2 字以上の名詞 | 「背景実行」（*background job*）、「基準線」（*baseline*）、「時間窓」（*time window*）、「根因」（*root cause*）、「移行の台本」（*script*）、「CI の見張り」（*watcher*）、「偽緑」（*false green*）、「生成器」（*generator*） | その分野で書くときの呼び名（「バックグラウンド実行」「ベースライン」「時間帯」「根本原因」「スクリプト」「監視」「ジェネレーター」）。カタカナ語や漢語になっても呼び名で書く。写真の背景、舞台の台本のような字どおりの使い方は残す |
| 英語の句を写した言い方 | 「足すものがない」（*add value*）、「〜レベルの設定」、「案はまだテーブルの上にある」 | 何がどう変わるか、どこに置くか、誰が決めるかを書く |

直訳語かどうかは「その分野の人が自分で書くときにその呼び名を選ぶか」で見る。**同じ記事やシリーズのほかの記事、同じリポジトリで繰り返し使っていることは、定着している根拠にしない**（AI と書いた文書の語が、次の文書にそのまま移っていることが多い）。本人が記事の中で定義した呼び名や、個人辞書にある語は残す。何を指すかが前後の文から決まらなければ、書き換え案を出さずに「何を指していますか」と尋ねる。

**定着した慣用句は対象外**:「骨が折れる」「手を焼く」「目から鱗」「首を長くして待つ」など。目安は「AIが広まる前の人の文章でもふつうに見かけるか」。見かけるなら残す。時計・機械・身体など文字どおりの「壊れる」も残す。

### A3. 非生物主語（擬人化）

道具・概念・ドキュメントが意志を持って動くように書く型。

- ✕「このドキュメントが API の仕様を語っている」→ ◯「このドキュメントに API の仕様が書いてある」
- ✕「コードが自らの振る舞いを証明する」→ ◯「コードを見ればどう動くか分かる」
- ✕「画面の配置が利用者の迷いを誘う」→ ◯「画面の配置が分かりにくくて、利用者が迷いやすい」

元の文にない動作主を捏造して主語に立てない（「チームが」「開発者が」を勝手に足さない）。「結果が〜を示す」のような定着した用法はそのまま。

### A4. 質感・認知を装う語と、体験の壮大化

一見具体的だが中身のない語。

- **質感を装う**: 手触り、肌感、温度感、熱量、血の通った、泥臭い
- **認知を装う**: 解像度（を上げる）、腹落ち、メンタルモデル
- **未定義の造語**: 「意思決定OS」のような勝手な比喩命名
- **壮大化の熟語**: 真理、境地、美学、深淵、極致、宿命、虚飾、結晶 など。個人のささやかな体験を教訓化する

※ これらは touyou さんが普段から使う語の可能性もある（特に「解像度」「熱量」）。**校正では「AIが足したっぽい箇所」に限って指摘**し、本人の文脈で自然に使っていそうなら流す。生成では、素材にない限り使わない。

### A5. 英語直訳の構文

- em ダッシュで挟む挿入（「重要な機能――とりわけ認証周り――は」）→ 助詞でつなぐ。生成での扱いは write-touyou の整形方針を正とする
- *delve into*:「〜に深く分け入る」→「詳しく見る」
- 否定対比（*it is not X, it is Y*）: 否定を外しても主張が変わらない飾りの対比だけ肯定文にする。「Xだと思われがちだけど実はY」のように**意味や比重を担っている否定は残す**（A1 の比重）

### A6. 後置ラベリング

- 「〜に他なりません」「〜と言えるでしょう」「面白いのはここです」「いかがでしたでしょうか」「〜の参考になれば幸いです」
- 推量で書かれている文は、削るときも推量の強さを保つ（A1 の言い切りの強さ）
- 「いかがだったでしょうか」「〜れば幸いです」は touyou さんも AI 以前から使っている（[`voice-baseline.md`](voice-baseline.md) 2 章）。何をしたかの振り返りや記事の中身と結びついているときは残し、定型の結びとして置かれているときだけ指摘する

前置きフィラー（「重要なのは」「結論から言うと」）と決め台詞は SKILL.md の「やってはいけない4つの操作」「避けるAI臭」で扱う。ただし「重要なのは」が**評価そのものを担っている**ときは、削らず「〜が大事です」と述語に残すのが yomiyasu の整理（A1 の文の働き）。

### A7. 間を作るだけの読点

短い主題・主語・目的語のすぐあとに、読み分けの役目のない読点を置く形（「このアプリは、」「Duo では、」「ただ、」）。AI と共作した記事では AI 以前の約 2 倍に増えている（[`voice-baseline.md`](voice-baseline.md) 4 章）。本人も「一拍止まりすぎる」と外している（[voice.md](voice.md) の個人辞書の具体例）。

- 指摘するのは、外しても読み違えが起きない読点だけ。長い主語や節のあと、並べた語の区切り、読み違えを防ぐ読点は残す
- 「読点を外しては？」と指摘するだけで、語順や述語は変えない。1 文に何か所もあるときにまとめて 1 件で指摘する

### A8. 2026 年に増えた言い回し

yomiyasu v2.5 が AI の文章によく出る言い回しとして挙げているもの。どれも、足りない中身が原文や素材にあるときだけ直す案を出す。

| 言い回し | 何が足りないか |
|---|---|
| 「〜という見立てです」 | 誰がそう判断したか |
| 「〜に潜む（リスク・罠・落とし穴）」 | 何が、どの操作のときに起きるか |
| 「〜が招く混乱」 | 何が原因で、誰が困るか |
| 「今や〜に欠かせない存在」 | 誰が、何をするときに要るのか |
| 「そこで効くのは」「ここで効いてくるのが」 | その工夫で何がどう変わるか |
| ルールを「契約」、確認の手順を「ゲート」、一覧を「台帳」と呼ぶ | 実際の中身（ルール、確認、記録）の名前 |

### A9. 漢語と和語は原文のまま

書き換え案で、原文の漢語を和語に開いたり、和語を漢語に硬くしたりしない。yomiyasu 3.0 は、推敲で「確認」を「確かめ」、「使用する」を「使う」、「現在」を「今」に開きすぎて戻す指示が増えた、という利用者の報告を受けてこの決まりを足している。逆向きの硬化（「使う」→「使用する」）は [voice.md](voice.md) の保護リストの動詞の行で止めている。この節は両方の向きをまとめて、案の中で語の硬さを変えない決まりにする。漢字とひらがなの書き分け（「その分」「そのぶん」）はこの節ではなく、本人の表記として触らない。

- その記事でふつうに使っている漢語（確認する、動作する、現時点）は残す。開いてよいのは、ほかの節で直す所（A2 の比喩、A4 の装う語、write-touyou の空虚な形容に挙げた「包括的」「多角的」など）だけ
- 書き換え案の中に、原文にない漢語や名詞化（「担保」「〜を実施する」「〜することが可能です」）を足さない。保護リストの動詞（「使う」「作る」「見る」）を漢語にしないのと同じ向き
- 他動詞を 1 語だけ名詞にして「の」で受ける形（「結果の確かめ」）を作らない。「結果を確かめる」と動詞で書く
- A2 の直訳語をその分野の呼び名に替えるのは、この節の「漢語を足す」に入らない

## B 節：取り入れない（touyou さんの文体と衝突する）

yomiyasu にはあるが、touyou さんの肉声を削るので**適用しない**。

| yomiyasu の規範 | 採らない理由 |
|---|---|
| 平均文長 30〜45 字、60 字超は分割、読点は 1 文 0〜2 個 | 連用形でつないだ長文が touyou さんのリズムの本体（操作3） |
| 補足カッコ（）を全廃 | カッコ書きの補足は保護リスト |
| 同じ文末を 3 連続させない／体言止めを交ぜる | 「〜と思います」の連続は肉声。体言止めはむしろ避ける側 |
| 「ぜひ試してみてください」を定型クロージングとして削る | 「〜してみてください」「〜してもらえればと思います」は保護リストの文末 |
| 「踏み込む」→「掘り下げる」へ言い換え | write-touyou では「掘り下げる」自体を空虚な動詞として避けている |
| 和欧文間の半角空白を一律削除 | touyou さんの表記ルールではない。揺れは `japanese-tech-writing.md` A3 で「不統一」として指摘するだけ |
| 「〜してください」「〜できます」への機械的な整理 | マニュアル向けの規範。語りかけの文体を硬くする |
| 箇条書き 15% 以下、漢字比率 20% 前後などの数値目標 | 数値で矯正しない（迷ったら触らない） |
| 「正直に言うと」「重要なのは」などの前置き、「いかがでしたでしょうか」「〜と言っても過言ではありません」「幸いです」などの結びを、語の形で削る | touyou さんは AI 以前からこれらを体験やツッコミと一緒に使っている（[`voice-baseline.md`](voice-baseline.md) 2 章）。A6 のとおり働きで見て、飾りのときだけ指摘する |
| 「言語化」を中身のない語として外す | 本人が AI 以前から主張の中心に置いて使っている語（同 2 章）。A4 と同じく、AI が足したっぽい箇所に限る |
| 同梱リンター（`yomiyasu_lint.py`）の文長・カッコ・文末チェック | 上の B 節の規範をそのまま警告にしているため、touyou さんの文章には誤検出になる |
