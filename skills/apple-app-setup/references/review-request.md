# レビュー依頼

App Store のレビュー依頼（評価のシステムダイアログ）を、使う人が**うまくいった直後**にだけ出す。

## 方針

- 出す場所はアプリごとに **1 か所**。「達成した」と本人が感じる瞬間を選ぶ（ハイスコア更新、コンプ、レッスンを終えた、
  リストを片づけた、など）。負けた・失敗した直後、作業の途中、起動直後には出さない
- ボタンや設定から呼ばない。システムは出すかどうかを自分で決める（1 年に 3 回まで）ので、押しても何も出ないことがある。
  設定に「レビューを書く」を置くなら、`https://apps.apple.com/app/id<APP_ID>?action=write-review` を開くリンクにする
- 1 つの版で 1 回まで。新しい版になったら、また条件を満たしたときに出してよい

## 出すかどうかの判定

UserDefaults に 3 つだけ持つ: 最初に起動した日、達成の回数、最後に依頼した版。

| 条件 | 既定値 |
|---|---|
| 最初の起動から経った日数 | 3 日以上 |
| 達成の回数（このアプリの「うまくいった」の数） | 3 回以上 |
| 最後に依頼した版 | 今の版と違う |

- 全部を満たしたときだけ出す。判定は純粋な関数（日付・回数・版 → 出すか）に分けてユニットテストする
- 達成の回数は達成のたびに 1 足す。依頼したら最後に依頼した版を今の版にする（回数は戻さない）
- 最初に起動した日は、記録が無ければ今日を書く。この仕組みを後から入れたアプリでは、既存の利用者もそこから数え始める
- スクリーンショット用の起動（見本データ・UI テスト）では出さない

## 呼び方

- SwiftUI の `@Environment(\.requestReview)`（StoreKit を import）。UIKit の `SKStoreReviewController` は使わない
- 結果の画面が出てから 1 秒ほど待って呼ぶ（画面の切り替わりと重なると、何が起きたか分かりにくい）
- 判定と記録は 1 つの型にまとめ、View からは「達成した」を伝えるだけにする。どの瞬間を達成とするかはアプリごとに決めて、
  その型の呼び出し元を 1 か所にする
- Debug ビルドでは毎回出る。TestFlight では出ない。本番での出方は確かめようがないので、判定のテストで担保する

## Android

Google Play の In-App Review API（`com.google.android.play:review-ktx`）。`ReviewManager.requestReviewFlow()` で
`ReviewInfo` を取り、達成の画面で `launchReviewFlow` を呼ぶ。出たかどうかはアプリから分からず、回数の上限も公開されていない。
判定の表は iOS と同じものを DataStore に持つ。動作の確認は `FakeReviewManager` か、内部アプリ共有で入れたビルドで行う。
