# アップデート後の新機能シート

アップデートした人にだけ、その版の新機能を最初の起動で 1 回見せるシート。実装の手本は touyou/Toreta の
`Toreta/Models/AppUpdate.swift` と `Toreta/Views/WhatsNewSheet.swift`。

## 方針

- **公開 API は無い**（Pages や Numbers の「新機能」シートは非公開。2026-11 に iOS 27 SDK と WWDC26 の資料で確認）。
  標準の SwiftUI 部品（`.sheet`、SF Symbols とテキストの行、下に `.borderedProminent` の「続ける」）だけで作り、
  WhatsNewKit などの依存は入れない
- TipKit の吹き出しにはしない（本人の判断）。`[measured]` シミュレータでは `Tips.configure()` 直後に設定した `@Parameter` が
  保存されず、Tip が出なかった
- 新しく入れた人には出さない。新機能が無い版（不具合修正だけの版）は項目を空にして出さない
- 文言は What's New と同じ温度で、冒頭にひとこと（「いつも〜ありがとうございます。今回は〜」）を置いてから項目を並べる。
  App Store の What's New と中身をそろえる

## 出すかどうかの判定

UserDefaults に「見終えた版」（`whatsNewSeenVersion`）を 1 つだけ持つ。

| 記録 | 手元のデータ | 判定 |
|---|---|---|
| 無い | 無い | 新規インストール。出さず、今の版を見終えたことにする |
| 無い | ある | この仕組みを入れる前の版から上げた人。出す |
| 今の版より古い | — | アップデート。出す |
| 今の版と同じか新しい | — | 出さない |

- 版の比較は `compare(_:options: .numeric)`（`1.9.0` < `1.10.0`）
- 記録は**シートを閉じたとき**（`.sheet(onDismiss:)`）に書く。起動時に書くと、出した直後にアプリを終えた人が見逃す
- 「手元のデータ」はアプリごとに決める（シリーズが 1 つ以上ある、記録が 1 件以上ある、など）。起動時に同期で読めるものを使う
- スクリーンショット用の起動（見本データ・UI テスト）では出さない

## 置き場所

- 判定は `App` の `init` で 1 回だけ行い、`@State` の Bool で持つ。シートは `WindowGroup` の root に付ける
- 版ごとの中身（あいさつ・項目）は 1 つの型にまとめ、リリースのたびにそこだけ差し替える
- 文言を持つプロパティは `LocalizedStringKey`（`String` で運ぶとカタログを引かない。[swiftui-rules.md](swiftui-rules.md)）
- 幅の広い画面では本文に `maxWidth` を掛け、iPad や Mac で行が横に伸びきらないようにする

## テスト

判定を純粋な関数（記録・今の版・データの有無 → 出すか）に分けてユニットテストする。最低限見るもの:
新規インストール、旧版からの更新、同じ版の再起動、`1.9.0` → `1.10.0`、新規インストールの後でデータを作ってから起動し直しても出ないこと、
閉じる前に終えたら次の起動でも出ること。

## Android

標準の仕組みは無い。Compose の `ModalBottomSheet` で同じ形を作り、見終えた `versionName` を DataStore（または SharedPreferences）に持つ。
判定の表は iOS と同じ。
