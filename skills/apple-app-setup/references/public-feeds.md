# 公開フィードを取り込むアプリ

外部の公開フィード（JSON の全件配布、RSS の新着）を取り込み、利用者がその項目に自分のデータ（進み具合・メモ）を
結び付けるアプリで、最初に決めておくこと。Patchday（touyou/patchday、CISA KEV・JVN・NVD を取り込む）で実際に
踏んだもの `[measured]`（2026-11、iOS / macOS 27）。通信や `Codable` の API そのものは Apple のドキュメントが正本。

## フィードの種類で、消し方と見せ方を分ける

フィードには「履歴を丸ごと配るもの」と「新着の窓だけを配るもの」があり、同じ扱いにするとどちらかで壊れる。

| 種類 | 例 | 取り込み | 見せ方 |
|---|---|---|---|
| 全件を配る | CISA KEV（JSON） | 届いた一覧に無い id は取り下げとして消す | **期限や日付の窓を既定で切る**。切らないと、過去の項目で一覧が埋まる（KEV は 1,700 件超のほとんどが期限切れで、そのまま出すと「期限切れ 1,762 件」になった）。窓の幅は設定にする |
| 新着の窓だけを配る | RSS | **id で重ねる**。取得のたびに差し替えると、窓から外れた項目（まだ期限が先のもの）が消え、利用者の進み具合とメモが宙に浮く。古い項目は自分の基準（期限が 1 年前より古い、など）で落とす | そのまま |

どちらも、**空の取得では何も消さない**（圏外や障害の応答を「全部取り下げ」と読まない）。

## 項目の id を変えない

利用者のデータは項目の id に結び付く。iCloud で同期するなら、id の形を変えた時点で全端末の進み具合が外れる。

- id には情報源の接頭辞を付ける（`kev:CVE-…` / `jvn:JVNDB-…`）。情報源をまたいで同じ番号が来ても混ざらない
- 代わりの情報源に切り替えると id の形が変わることがある（JVN iPedia と jvn.jp）。圏外のたびに切り替えると、
  項目が消えて戻るのをくり返す。切り替えるのは、元の情報源が計画停止を返したとき（503 や HTML のお知らせ）だけにする

## 取得

- **行ごとに読む**。1 行の null や欠けた項目で配列全体のデコードを落とさず、読めない行だけ落とす
- **日付は暦日で持つ**。期限のような「日」を取得した端末のタイムゾーンの瞬間で持つと、別のタイムゾーンで 1 日ずれる
- 大きくて変わらない日が多いフィードは、ETag と Last-Modified を残して条件付きで頼む。304 なら前回の分を使う
- 回数に上限のある API は、ほかの情報源の更新と切り離して後ろで取る（引っ張って更新の表示は、速い情報源が取れたら止める）。
  後ろの取得が書いた分を、先に取った古い写しで上書きしないよう、**写しは取得を待ったあとに作る**
- 取り直しの途中で更新の Intent が呼ばれたら、走っている分の終わりを待つ（古いまま「更新しました」と返さない）
- Background Assets は版ごとに決まったアセットを先に落とす仕組みで、毎日変わる公開フィードには合わない

## 開くリンクと通信先

- フィードに入っているリンクは、https かつ情報源の運営元のホストのものだけを開く
- 通信先のホストを増やしたら、プライバシーポリシーとストアの掲載文も同じ PR で直す

## 拡張から読む

ウィジェットや Intent の拡張は、アプリが App Group に書いた写しを読む。拡張のプロセスは起動したときの写しを
持ち続けるので、Intent と Query の前に読み直す。
