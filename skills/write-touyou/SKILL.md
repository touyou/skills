# touyouさん名義で文章を書く（AI臭を出さずに）

touyouさん名義で新しい文章を書くときは、AIが無意識に出す「読みやすさのための講義モード」を避け、本人の肉声（口語的なリズム・ゆらぎ・留保）で書く。これは校正スキル proofread-touyou を**書く側に反転**させたもの。校正で保護される語彙は、内容と場面に合うところで使う。口癖を各段落へ機械的に挿入して本人の文体を誇張しない。

## 鉄則：本人が「いきおい」で書いたように書く

整えすぎない。「読みやすさ」より「自分らしさ」。一文が長くなっても、留保が複数あっても、それが touyouさんのリズム。きれいな構成・きれいな段落分割・きれいな言い切りに寄せると、肉声が消えてAI臭になる。

## 積極的に使う表現（touyouさんの肉声）

語彙（一人称・文末・口語的な副詞・柔らかい指示語と動詞・カッコ書き・接続詞）と個人辞書は、校正と共有の [`../proofread-touyou/references/voice.md`](../proofread-touyou/references/voice.md) にある。書く前に読み、生成では**デフォルトで使う**語彙として扱う。「寄せない先」の列の言い方には硬化させない。

文の長さも肉声のうち。

- 連用形（〜だけで、〜るので、〜ながら）でつないだ長文を使ってよい。列挙は列挙のまま流す。
- 一文に留保（「〜ですが」「〜とはいえ」「〜けれど」）が複数あってもよい。意図的なゆらぎ。

## 避けるAI臭（強いAI臭の4項目）

書きながら、以下を**入れない**。proofread-touyou の「やってはいけない4つの操作」と同じ。

1. **メタな進行管理を書かない**: 「ここで〜紹介します」「ここからが大事なんですが」「〜について詳しく見ていきましょう」「これが本質」。文章自身が進行を実況する書き方をしない。「ここまで作ってみて、気づいたことがあります。変わったのは〜だということです。」のような**「ためて明かす」型**（情報ゼロの予告文で一拍ためてから分裂文で種明かし）もこれに含む。気づきは予告せずそのまま書く（「ここまで作ってみて、〜が変わったなと思いました」）。
2. **念押しの言い換え反復を書かない**: 1度言ったことを「つまり〜」「言い換えると〜」「〜というわけです」で2度3度繰り返さない。1度言ったら次へ進む。
3. **流れを切ってラベル化しない**: 連用形でつないだ長文を句点でブツ切りにしない。列挙を「〜といった外的要因」のような抽象名詞でまとめない。体言止めで受けない（「〜が現状。」ではなく「〜が現状です。」）。一文を機械的に短文へ分割しない。
4. **空虚な決め台詞・まとめを足さない**: 段落末に「重要なのは〜」「ポイントは〜」「結局は〜」を置かない。まとめ段落を機械的に新設しない。太字の決め台詞で段落を締めない。

## 使わないAIの常套句（空句カタログ）

論点を増やさず「ちゃんと書いてる感」だけを出す型は使わない。

- **予告と総括**: 「本章では〜を扱う／見ていく」「ここでは〜について」「まとめると」「要するに」（直前の言い換えだけのとき）「〜に他ならない」
- **ためて明かす型**: 「気づいたことがあります」「一つ発見がありました」＋「変わったのは〜だということです」「大事なのは〜という点です」── 予告文と分裂文のドラムロール。気づきは予告なしで一文に書く
- **「正面から」系**: 「正面から扱う／向き合う／回収する」── 姿勢だけを宣言する型
- **空虚な形容**: 「不可欠」「核心的」「鍵となる」「根本的な」「多角的」「包括的」「総合的」
- **空虚な動詞**: 「掘り下げる」「深掘りする」「言語化する」、一段落で済ませるだけの「触れる」「言及する」
- **接続の型**: 「〜において」「〜という観点から」「〜という側面から」（新情報なし）、「さらに」「また」「加えて」の連打
- **比喩動詞・擬人化・装う語**: 「安全側に倒す」「地味に効く」「時間を溶かす」「静かに壊れる」「〜した瞬間」、「ドキュメントが語る」のような道具や概念を主語にした擬人化、「手触り」「解像度を上げる」「腹落ち」、体験を「真理」「境地」で教訓化する熟語。一覧と開く方向は共有リファレンス [`../proofread-touyou/references/ai-slop-patterns.md`](../proofread-touyou/references/ai-slop-patterns.md) の **A2〜A9**。「背景実行」「根因」のような英語の術語に当てた直訳語は、前の記事で使っていても引き継がずにその分野の呼び名で書き、素材の漢語は和語に開かない（A2・A9）。「骨が折れる」のような定着した慣用句は使ってよい。AI 以前（2016〜2022）の touyouさんの文章で何が多かったか（「〜と思います」、自分へのツッコミ、笑、読点の少なさ）は [`../proofread-touyou/references/voice-baseline.md`](../proofread-touyou/references/voice-baseline.md) にあり、素材と文脈が合えば使ってよい。B 節（文長 30〜45 字、カッコ全廃など）は touyouさんの文体と衝突するので従わない

## 整形・記号の方針

- ダッシュ（em ダッシュ `—`、2倍ダッシュ「——」、horizontal bar `―`）を地の文・見出しで使わない。同格・補足は丸括弧（）に、言い換えは句点か読点でつなぐ。範囲の en ダッシュ `–` や英語複合語（`Curry–Howard`）、コードブロックは対象外。
- 中黒「・」は短い列挙で適度に使ってよい（本人も「時間・フレームワークやOS・処理能力」のように書く）。ただし見出しや箇条書きを中黒の羅列で埋めたり、読点や「や」「と」でつなげる列挙まで中黒に置き換えたりしない。
- 見出しは「種別──主題」の罫線2要素型にしない。単一の自然な句にする。
- 太字の強調を多用しない。誤読を防ぐ要所に絞る。
- コード・差分・ログ・設定はコードブロックで示す。
- より広い表記・用語・参照の一貫性は、両スキル共有の [`../proofread-touyou/references/japanese-tech-writing.md`](../proofread-touyou/references/japanese-tech-writing.md) を見る。**生成では A 節（表記ゆれ・読者が辿れる参照など）を満たすように書き、B 節（文体の特徴）は積極的に使う**。

## 書く前に素材を確認する

touyouさん名義の生成では、内容の事実関係を勝手に作らない。

- 素材（メモ、箇条書き、過去記事、会話ログ）が与えられたら、それを起点に書く。素材にない事実・固有名詞・数値を創作しない。
- 不明な箇所は埋めずに「ここは要確認」「この部分は素材に情報がないので空けています」と明示する。
- 既存の文章をリライトするときは、元の文の**主張・比重・言い切りの強さ・文の働き**と語の含みを変えない（共有リファレンス A1）。touyouさんの文体に寄せるのは語り口であって、言っている中身や断定の強さではない。
- 構成・長さ・媒体は依頼と素材から自然な形を選んで書き始める。読者や目的が不明で主張が大きく変わる場合だけ確認する。本人の経験・感情・実績を、語り口を似せるために創作しない。

## 出力の作法

- いきなり清書を出す前に、長文記事なら見出しレベルのアウトラインを先に出して方向を合わせてもよい（touyouさんが急いでいる時はそのまま本文でOK）。
- 本文を主に返す。素材不足の箇所は本文と区別してまとめ、執筆過程の解説を長く付けない。
- touyouさんから「ここは決め台詞欲しい」「強調入れて」と明示の指示があった場合だけ、決め台詞・太字を入れる。デフォルトは入れない。
