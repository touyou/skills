# Test Effectiveness ルーブリック (1-5)

カバレッジ%（Tier 1）は「**何行が実行されたか**」しか見ない。このルーブリックは「**実行されたとして、それは振る舞いを実際に検証しているか**」を判定する。

## 判定対象

テストファイル（`*.test.ts` / `*.spec.ts` 等）のサンプリング。テスト不在の場合は `null`。

## 評価軸

1. **assertion の質**: 何を assert しているか（戻り値だけ vs 副作用 vs 状態遷移）
2. **edge case の網羅**: null、空、境界値、エラー経路をテストしているか
3. **mock の妥当性**: モックしている境界が適切か（外部 I/O は mock OK、ロジックの mock は減点）
4. **タイトル vs 中身の整合**: テスト名が示すものを実際にテストしているか
5. **assertion 密度**: 1テストあたり1個以上の意味ある assert があるか（snapshot だけのテストは弱い）

## レベル定義

### 5 — 実効性が高い

- assertion が振る舞いを直接検証している（戻り値+副作用+エラー経路）
- edge case（null、空、境界、例外）が体系的にテストされている
- mock は外部依存（HTTP, DB, FS, 時刻）に限られ、ロジックは実物が走っている
- テスト名と中身が一致しており、失敗時に何が壊れたかが特定できる
- snapshot test が使われていても、本質的な assert と併用されている

### 4 — おおむね有効

- 大半のテストが意味ある assert を持つ
- edge case は主要箇所をカバー、ただし一部の関数は happy path のみ
- mock の使い方は妥当だが、稀にロジックを mock してテスト自体が空洞化している箇所がある

### 3 — 平均的

- happy path 中心、edge case は散発的
- assertion が薄いテストが混ざる（"expect(result).toBeDefined()" のような弱い assert）
- snapshot test の比率が高めで、振る舞いの検証より「変わってないこと」のテストが主

### 2 — 形だけのテスト

- 多くのテストが「呼び出して例外が出ないこと」だけを確認
- mock が広範に使われ、実際にコードがロジックを実行していないテストが多い
- テスト名が漠然（"works correctly"、"basic test"）で何を検証しているか不明

### 1 — テストの体をなしていない

- assert がない、または `expect(true).toBe(true)` レベル
- describe/it の構造はあるが内部が空または常に通る
- カバレッジ数値を埋めるためだけのテストが大半

## 判定手順

1. サンプリングされたテストファイルから10件程度の `it` ブロックを抽出
2. 各ブロックについて: assert 数、何を assert しているか、mock の有無と対象を記録
3. テスト名と中身の整合をスポットチェック
4. 全体傾向から 1-5 を1つ選ぶ

## サンプル不足時の挙動

サンプリングされたテストファイル数が **3 未満**、または `it` ブロックが 10 個未満の場合:

- **default = 3** にする
- 1 ファイルだけ「すごく良いテスト」を読んで Score 5 にしないこと（他 8 ファイルがどうかわからない）
- `confidence: "low"` を必ず設定する
- rationale に「N 件のテストファイル/M 件の it ブロックから判定」を明記
- そもそもテストファイルが 0 件の場合: スコアは `null`、`confidence: "n/a"`、rationale に "no test files detected" と記載

## 注意：カバレッジとの関係

- カバレッジ高 + 実効性低: 「テスト書いてあるけど assertion 弱い」典型。Tier 1 と Tier 2 の差で見える
- カバレッジ低 + 実効性高: 「書いてあるテストはちゃんとしているが、量が足りない」
- カバレッジ高 + 実効性高: 健全
- カバレッジ低 + 実効性低: 危険

このルーブリックは Tier 1 のカバレッジと**独立して**判定する。両方見ることで初めて「テスト品質」がわかる。

## rationale の書き方

⭕ "10ブロックを確認。3ブロックは戻り値+副作用を assert、4ブロックは戻り値のみ、3ブロックは expect.toBeDefined() のみ。edge case は src/auth に集中、他モジュールは happy path 中心。Score 3."

❌ "Tests look reasonable"
