# Cohesion ルーブリック (1-5)

モジュール内の凝集度を 1-5 の離散値で判定する。各レベルは**観察可能な基準**で書く（主観的な形容詞を避ける）。

## 判定対象

サンプリングされた代表ファイル群（モジュール/ディレクトリ単位の振る舞い）。

## 評価軸

1. **責務の単一性**: 1つのモジュール/ファイルが扱っている関心事の数
2. **エクスポートの一貫性**: 公開 API 同士が同じ抽象レベルにあるか
3. **内部関数の関連性**: 同じファイル内の関数同士が共通の状態/データを扱っているか

## レベル定義

### 5 — 高凝集

- 各モジュール/ファイルが1つの明確な関心事に閉じている
- エクスポートが揃った抽象レベル（例: 全部 React component / 全部 service function）
- 「このファイルを名付けるなら」という問いに1単語で答えられる
- 関連しない utility 関数が混在していない
- **Coordinator/orchestrator パターンは単一責務とみなす**: Page コンポーネント、Editor コンポーネント、Container コンポーネント等が多数の component/hook を import するのは正当（責務 = "X を組み立てる"）。以下を満たせば level 5: (1) ロジックは hook/util に分離されている、(2) JSX/return が宣言的に組み立てているだけ、(3) 状態の保持/変更ロジックを直接持っていない

### 4 — おおむね高凝集

- 大半のファイルが単一責務だが、一部に「雑多な util.ts」が混ざる
- エクスポートの抽象レベルがほぼ揃っているが、稀に格下/格上のヘルパーが公開されている

### 3 — 中程度

- ファイルあたり2-3の関心事が混在している箇所が散見される
- "manager"、"handler"、"helper" など曖昧な名前のファイルが複数ある
- React component と data fetching ロジックが同じファイルにあり、分離の余地がある

### 2 — 低凝集

- 1ファイルで複数の無関係な責務（UI + データ層 + バリデーション）が同居
- 「このファイルは何をするか」を1文で説明できないファイルが半数以上

### 1 — ばらばら

- ファイル/モジュールの境界が機能の境界と一致していない
- グローバル util、misc、common などのバケツファイルに大量のコードが詰まっている
- 同じ関心事が複数ファイルに散らばっており、凝集度の概念が機能していない

## 判定手順

1. サンプリングされた各ファイルを読む
2. 各ファイルについて「責務の数」と「抽象レベルの一致」をメモ
3. 全体の傾向から1つの 1-5 値を選ぶ
4. rationale を150字以内で書く（具体ファイル名/シグナルを必ず含める）

## サンプル不足時の挙動

サンプリングされたファイル数が **5 未満**、または「責務の数を判定できる規模のファイル（30行以上）」が 3 未満の場合:

- **default = 3**（"中程度"）にする。観察証拠が無いまま 4 や 5 を付けない
- 例外: 強いポジティブシグナル（全ファイルが小さく明確）または強いネガティブシグナル（util バケツファイルが目に見えて存在）があれば 4 / 2 に振ってよい
- `confidence: "low"` を必ず設定する
- rationale に「サンプル N 件のため断定できず」を明記する

## rationale の書き方（重要）

抽象的な評価語を避け、**観察した具体的事実**を書く:

❌ "Cohesion is generally good with some room for improvement"
⭕ "src/utils/index.ts に format/validate/api 呼び出しが同居しており分離の余地。残り18ファイルは責務単一。Score 4."

これがないと、後で score だけ見ても再現性が確認できない。
